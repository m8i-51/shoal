# 操作グラフ（画面 → 操作 → 次の画面）

日付: 2026-10-19

## 問題

サイトマップは path を訪れたかだけを記録する。同じ path に 2 ターン滞在すると `explored` になる。

これだと、`1→2→3→4→5→6` と進んだあと `1→2→3→4→5→7` を試せない。途中の操作を「押した」時点で済みにすると、先の兄弟分岐が閉じる。

## ゴール

- run をまたいで、画面と操作と遷移先を残す
- 先に未探索がある間は、途中の操作を済みにしない
- ゴールのないブラウザ探索に、次の一手のヒントを出す

## 決定事項

### 記録

- 永続先: `coverage/explore-graph.json`（gitignore 済み `coverage/` 配下）
- 画面は path（サイトマップと同じ正規化）
- 操作はアクセシビリティスナップショットの名前付き clickable（button / link / tab など）
- 成功した click だけを「押した」にし、遷移先 path を辺にする
- 画面から消えた未押し操作は落とす。押した操作は、メニューが閉じても残す

### 次の一手

1. その画面に未押しの操作があれば、それを押す
2. 全部押し済みなら、先の未探索までが一番近い操作をもう一度押す
3. 先が全部探索済みなら、戻るかスクロールする

未観測の遷移先は未探索として扱う。画面同士の循環は探索済みとして打ち切る。

### 誰に渡すか

- ヒントを出すのは、シナリオのない browser レーンだけ（自由探索と lens）
- シナリオ・回帰・検証はグラフに記録するが、ヒントでは誘導しない
- クリックはスクリプトが代行しない。ペルソナが選ぶ
- 人事の `get_path_coverage` に、未押しの操作が残っている画面を添える

### 上限

- 画面 2000、1 画面あたり操作 60
- ログアウトなどサイトマップが除外する path は記録しない

## やらないこと

- 未押しがあるときのクリック拒否
- ダッシュボードへの操作グラフパネル
- API 探索レーンへの適用
